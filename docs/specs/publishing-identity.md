# The studio's public identity

The apps ship under `com.flegm.mercato` so no personal name appears on a store
listing. That was only half the change. Three other things a player or a store
reviewer can read still carried a real name, and this file records what was
done about each and what is left to do by hand.

None of the remaining steps can be automated from here: they are account
actions, and one of them is a key that must never pass through anyone else's
hands.

## 1. The privacy policy URL — needs a GitHub organisation

Both stores print the privacy policy URL on the public listing, and the app
links to it from Settings. It used to be:

    https://nicogaray7.github.io/mercato/privacy

which is the personal account, name included. Both apps now point at:

    https://flegm-project.github.io/mercato/privacy

Done: the organisation exists, this repository was transferred into it, and
Pages is enabled on `main` from `/docs`. `flegm` itself was taken by an
unrelated GitHub user, hence `flegm-project`.

The URL still 404s, and only because the page it points at is not committed
yet. See the next section: it comes back the moment there is an address to
print on it.

The repository name stayed `mercato`, so the path did not change, and GitHub
left a redirect behind the old owner, so old clones and links keep working.

## 2. The contact address — needs a neutral mailbox

The three policies used to print a personal address. They now print whatever
`docs/legal/contact.txt` holds, in one place for all three languages, and
`scripts/gen-privacy-site.mjs` refuses to build while that file still holds its
placeholder. That refusal is the point: a privacy policy exists to be read by
strangers, and the address on it goes on both store listings.

`docs/privacy/index.html` was deleted rather than left in place, because the
committed copy still printed the old address and would have been the first
thing Pages served.

To finish:

1. Create a neutral mailbox, e.g. a free account under the studio name.
2. Put it in `docs/legal/contact.txt`.
3. `node scripts/gen-privacy-site.mjs`, then commit `docs/privacy/index.html`.

The same address answers App Store Connect's support URL requirement, which is
still open (see release-checklist.md).

## 3. The Android signing key — must be generated by its owner

This key is what lets the app be updated for the rest of its life. Lose it and
the listing cannot be updated, only replaced under a new package name. So it is
generated by the person who will keep it, with a password that has never been
anywhere else, and this repository is already arranged to receive it without
ever storing it: `*.jks` and `keystore.properties` are both gitignored, and
`app/build.gradle.kts` reads the passwords from that file or, in CI, from the
environment, leaving the release build unsigned rather than failing when
neither exists.

Generate it outside the repository:

    keytool -genkeypair -v \
      -keystore ~/mercato-upload.jks \
      -alias mercato-upload \
      -keyalg RSA -keysize 4096 -validity 10000 \
      -dname "CN=Flegm, O=Flegm, C=FR"

`keytool` asks for the password twice and writes nothing else. Then create
`apps/android/keystore.properties`, which git already ignores:

    storeFile=/Users/<you>/mercato-upload.jks
    storePassword=<the password>
    keyAlias=mercato-upload
    keyPassword=<the password>

Then back it up somewhere that is not this machine, and enrol in Play App
Signing when the first bundle is uploaded, so Google holds the app signing key
and this one is only the upload key: that is the arrangement where losing it is
recoverable.

Verify with `./gradlew :app:bundleRelease`, which should stop reporting an
unsigned bundle.
